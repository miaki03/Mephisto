# 15 · 接入方式：校园网怎么出去

> **定案（2026-10-28）**：走 **Cloudflare Tunnel（路线 B）**。理由：零成本、今天就能通、手机 URL 干净（标准 443、不带端口号）。
> 代价（已知并接受）：**TLS 在 CF 边缘终结，它看得到明文**；CF 侧有 125 秒读超时与 100 MB 单请求上限。
> **路线 A（VPS + frp）保留在 [16](16-network-runbook.md) 里作为退路**，切换时 App 只改一个地址。
> **删掉 Tailscale**（校园网打洞不可用，且你不依赖免费中继）；**IPv6 直连**仅作旁路。
> **Clash 不用管**——它只在路由层接管本机出站，不影响我们的入站服务。
>
> 📋 **要动手时看 [16 接入施工手册](16-network-runbook.md)**：两条路线的完整配置、验收命令、故障表都在那。

---

## 1. 为什么校园网把方案收敛到"主动出站"

| 现实 | 后果 |
|---|---|
| 你在 NAT 后面，可能还有一层校方 NAT | 没有公网 IP，端口映射 / DDNS 全部不成立 |
| 校园网对 UDP 打洞限制多、且不稳定 | Tailscale / ZeroTier 大概率**永远走中继**，而你不想依赖免费中继 |
| 校园网常对入站连接做过滤 | 即使有 IPv6，"别人连进来"也不保证通 |
| 校园网可能夜间断网 | 长连接会周期性断，**执行节点不是 7×24 保证** |

**结论：只有"由你的机器主动向外建连接"这一种结构能成立。** 两条路都是这个结构——frp 是主动连 VPS，cloudflared 是主动连 CF。

## 2. 四条路线的最终定位

| | 路线 | 定位 | 成本 | 说明 |
|---|---|---|---|---|
| **B** | **Cloudflare Tunnel** | ✅ **定案** | 0 元 | 手机 URL 干净（443 无端口）；代价是明文经 CF 边缘 |
| A | VPS + frp | 退路 | ¥20–40/月 | TLS 在你自己手里；切换只改 App 里一个地址 |
| — | 域名 + IPv6 直连 | ❌ 不可用 | 0 元 | 实测本机无全局 IPv6、无 v6 默认路由 |
| — | Tailscale / Headscale | ❌ 删除 | 0 元 | 校园网下必退回免费中继 |

> **更正**：我曾在上一版把 Cloudflare Tunnel 列为"不做"，理由是 quick tunnel 的 SSE 不实时、长请求撞 524。前者只对 `trycloudflare.com` 快速隧道成立（named tunnel 不受影响），后者已核实为 **125 秒**且我们用异步设计规避。所以那两条理由不构成否决。

## 3. 方案 B 的具体形状

```
手机 ──HTTPS(443)──► Cloudflare 边缘 ──隧道──► cloudflared（家里 PC）
                                                    │ 出站连接，穿 NAT
                                                    ▼
                                            mephisto serve 127.0.0.1:8787
                                                    │
                                                    └─► dsh 子进程
```

**四条性质**：

1. **PC 不需要任何入站端口**，只建一条出站连接。
2. **手机不需要装 VPN**，`https://你的域名` 直接可用。
3. **真证书由 CF 提供**，Android 明文 HTTP 的限制问题不存在。
4. **服务端只听 `127.0.0.1`**，公网入口在 CF。

**两条代价**（已在 §1 声明，不再重复辩护）：明文经 CF；125 秒/100 MB 的限制要求我们把长任务做成异步、把附件做成分片（见 [17](17-attachments.md)）。

## 4. 部署要点（B 版，详细命令见 [16](16-network-runbook.md) §2）

| 组件 | 装在哪 | 干什么 |
|---|---|---|
| `cloudflared` | 家里 PC | 建一条**出站**连接到 CF，把 `127.0.0.1:8787` 暴露成 `https://你的域名` |
| `mephisto serve` | 家里 PC | 只听 `127.0.0.1:8787`，**不绑 `0.0.0.0`** |
| DNS / 证书 | CF | CNAME 指向 `<TUNNEL_ID>.cfargotunnel.com`，证书由 CF 自动签发 |

**三个注意点**：

1. `config.yml` 里加 **`protocol: http2`**——QUIC 在部分网络被拦，而且 SSE 在 HTTP/2 更稳。
2. 不要把 `trycloudflare.com` 快速隧道当正式通道（它会缓冲 SSE）。
3. 长任务与附件都受 CF 超时约束 → 前者异步化，后者分片化（[17](17-attachments.md)）。

## 5. 落地顺序（每一步都可单独验收）

| # | 在哪 | 做什么 | 验收 |
|---|---|---|---|
| 1 | CF 控制台 | 域名 NS 托管到 CF | 站点状态 Active |
| 2 | PC | 装 `cloudflared`，`tunnel login` / `create` / `route dns` | `tunnel list` 里有 mephisto |
| 3 | PC | 写 `config.yml`（含 `protocol: http2`） | `tunnel ingress validate` 通过 |
| 4 | PC | `mephisto serve` + `cloudflared tunnel run` | 本机 `curl 127.0.0.1:8787/healthz` 通 |
| 5 | 手机 | **关 Wi-Fi 用 4G** 打开 `https://你的域名/healthz` | 有 JSON ★关键 |
| 6 | PC | 注册计划任务开机自启 | 重启后手机仍能连 |
| 7 | PC | `curl -N https://你的域名/events` | **逐行出**，不是一次性吐 ★SSE 生死线 |

## 6. Clash：不用管，但要留一道保险

上一版我说"Clash 是 TUN 模式会抢流量，要先加直连规则"——**这是我根据代理环境变量猜的，你已确认不成立，删掉。**

真实情况是：Clash 只服务于 dsh 的网页请求，Windows 不走强制代理。所以：

| 影响面 | 结论 |
|---|---|
| frp 隧道 | **不受影响**（frp 不读 `HTTP_PROXY`） |
| 我们的 HTTP 服务 | **不受影响**（服务端只听入站） |
| dsh 的子进程 | **应当继承代理**——它要访问 GitHub 等，行 |
| 我们自己的内部调用 | **要显式禁用代理**，见下 |

**唯一要留的一道保险**：我们的进程如果继承了 `HTTP_PROXY`，那么 `127.0.0.1` 的内部调用有可能被带走。所以内部调用一律显式 `trust_env=False`（或 `proxies={"http": None, "https": None}`）。这是一行代码的事，但漏了会变成"本地调用莫名超时"。

## 7. 服务端参数（比上一版更简单）

```toml
[server]
host = "127.0.0.1"    # 只听回环，公网入口在 Cloudflare 上
port = 8787
trust_env_proxy = false   # 内部调用不读 HTTP_PROXY
```

**不需要 `0.0.0.0`**。这是隧道方案的直接红利：机器上一个入站端口都不开。

## 8. 「它在思考，还是死了」

四态，判据不变：

| 客户端显示 | 判据 |
|---|---|
| 空闲 | 无运行中 job |
| **思考中 12s** | 有 job + 15 秒一次 `: ping` |
| **无进展 75s** | 有心跳但 60 秒无新事件 |
| **连接中断** | 45 秒未收任何字节 → 重连 + 续传 |

**新增一条校园网专属**：CF/cloudflared 那侧如果断（隧道断了、校园网断网），SSE 会自然断，客户端进"连接中断"；重连失败 3 次后提示"服务端离线"，并**降级到只用本地闹钟**。手机上的提醒不受影响。

## 9. 夜间断网怎么办

校园网常在 23:30–6:00 断网或认证失效。影响与对策：

| 场景 | 影响 | 对策 |
|---|---|---|
| 提醒到点 | **不影响**（手机本地闹钟） | 已经这么设计了 |
| 你半夜发消息 | 发不出去 | App 显示"服务端离线"，消息排队等恢复 |
| 定时任务（如夜间摘要） | 跑不了 | 摘要窗口改成"凌晨 6:30 补跑"，或干脆改到 23:00 前 |
| PC 自己 | 可能被要求重新认证 | `cloudflared` 与 `mephisto` 都设开机自启 + 断线重连 |

**这条再次验证了「两级通知」的必要性**：实时层依赖网络，准点层不依赖。

## 10. 鉴权（暴露公网后更要紧）

| 项 | 做法 |
|---|---|
| 形式 | `Authorization: Bearer <token>` |
| 存储 | 服务端只存 `sha256(token)` |
| 签发 | `python -m mephisto device add --name 手机`，打印一次 |
| 吊销 | 删 `device` 行 |
| 限流 | 每 IP 每分钟 60 次，超了 429（防扫） |
| 可选加固 | CF Access（邮箱 OTP 或服务令牌）、固定 IP 白名单、只放行 `/api/v1/*` |
| 日志 | 不记 Authorization 头，不记正文 |

## 11. 明确不做

| 不做 | 理由 |
|---|---|
| Tailscale | 校园网打洞不可靠，且你不依赖免费中继 |
| DDNS | 校园网，无意义 |
| 端口映射到公网 | 做不到 |
| VPN 客户端装到手机 | 隧道方案不需要 |
| 把 PC 暴露到公网 | 只让 CF 暴露，PC 只建出站连接 |
| 快速隧道 `trycloudflare.com` | 会缓冲 SSE，只能当临时看页面用 |

## 12. 验收

```powershell
# 1. 手机 4G 打开 https://你的域名/healthz      → 有 JSON
# 2. curl -N https://你的域名/events            → 逐行出（SSE 生死线）
# 3. 断网再恢复                                  → SSE 自动重连、消息不丢
# 4. 错误 token                                  → 401
# 5. 杀掉 dsh 子进程                             → 5 秒内看到 job_failed
# 6. 停掉 cloudflared                            → 手机 45 秒内显示「连接中断」，恢复后自动续传
# 7. 传一个 64 MB 文件（16 片）                  → 校验通过；传 90 MB → 客户端直接拦住
```
